## Caption system
All captions are natural Indonesian meaning units, even for English narration. At 1080×1920 use the same 44px base size in every location; scale consistently for another resolution. Keyword weight/color may differ, regional font size may not. Each WORD has its own background; a phrase enters together and stays still while being read, rather than mandatory karaoke.

Nine allowed anchors: top-left/top-center/top-right; middle-left/middle-center/middle-right; bottom-left/bottom-center/bottom-right. The column determines alignment for EVERY line: left=left, center=center, right=right. Emphasis modes do not change alignment. Select the anchor and line breaks around meaning, faces, props, logo and platform UI; there is no requirement to use all nine in one film. Overlay coordinates stay independent of the scene camera.

Current conservative reading envelope: x90..900,y280..1240 at 1080×1920. Current anchors: x110/540/880, y300/960/1220; top/middle/bottom align the whole text block respectively. Keep the entire entrance path and word rectangles in the envelope; reserve right and bottom for TikTok/Instagram controls, account/profile and caption areas. This is a project layout convention, not a guarantee against every device/expanded platform caption. Animate in with a short directional slide+fade (V12: 7 frames), then a stable hold and clean exit. Do not add blinking/pulsing while reading.

## Stable rendering and review
Observed V11 failure: captions disappeared intermittently at18–19,52–53,55–56s, and martabak at35–36,46–47s despite valid geometry. V12 fixed it using native SVG caption text/word backgrounds, SVG focus filters, CPU raster/compositing, root SVG remount each frame, and a frame-ready wait (70ms then two animation frames). On this Mac, scripts/chrome-cpu-render.sh disables GPU/raster/compositing, render-v12.mjs uses concurrency1. SwiftShader/ANGLE produced horizontal strips and was rejected. Preserve the proven path when deriving the next version; only adopt faster settings after moving-frame evidence passes. These are machine-specific findings, not a universal requirement on every device.

Inspect a short moving proof before the full export, then verify the actual final export. Check entrances, hold frames, object visibility, transition continuity, face/prop/caption collisions and clipping. A still, valid source, geometry audit or successful decode cannot prove no flicker.
