# Storyboard-first workflow — autonomous production

Latest explicit user authorization, 1 November 2026: no need to request approval to generate audio for a NEW script; no need to request storyboard ACC. This supersedes previous “present storyboard and wait for acceptance” instructions.

When the user supplies a new script for video production, proceed through editorial assessment → written storyboard/shot plan → character/layout and transition tests → narration/timing and implementation → creative/technical QA → local final export. Think before building: identify audience, hook, emotional turn, action/reaction, focal point, camera motivation and both sides of each transition. Storyboard FIRST remains required; waiting for the user to approve it is NOT required. Save it and provide concise progress updates while continuing work. Do not ask “boleh lanjut?”, request storyboard ACC, or ask again for audio credit permission covered by this authorization.

Treat the supplied script as creative input, not a sequence of slides. Improve visual storytelling and routine editorial flow while preserving the intended meaning. Do not silently replace the story's message or invent substantive spoken claims. Ask only when missing information materially prevents a faithful result; continue independent work meanwhile. A later explicit user request to review/approve a plan, work only on documentation, or avoid rendering/audio controls that task.

For a genuinely new spoken script requested for production, generate the needed narration directly with the configured/chosen voice (current story: Leya; inspect cached generation metadata instead of guessing a voice ID). Estimate and record credits as production information, not an approval gate. Cache requests/results and resume/poll a job rather than creating duplicate takes. No arbitrary regeneration of the same script, voice shopping or unbounded retries. If a request/job outcome is ambiguous, inspect the existing job/cache before spending again; report a real account/service failure rather than repeatedly creating generations.

For visual-only revisions, reuse the ACTUAL existing audio file and timing, with zero new synthesis. For requested spoken edits, reuse unchanged passages and generate only the necessary changed material where practical; the authorized spoken edit covers its needed generation. Resolve the actual component, narrationFile, timing and lead from Root.tsx, never choose by version number alone. Approved V18 uses public/narration.mp3 with src/timing-v18.json; V12 apology story uses narration-v7.mp3/timing-v7.json. Same voice ID with resynthesis still costs credits and is not reuse.

Use the connected ElevenLabs OAuth MCP; do not ask for an API key on that route or copy credentials into notes. Preserve prior outputs. Authorization covers production requested by the user, not arbitrary future jobs, unrelated purchases or external publication. Saving skills/profile alone does not trigger a video/audio generation. Publish externally only if asked.

For approved art direction, captions, characters, outro and stable rendering, read approved-v18.md. The latest approved baseline is V18; historical V7/V8 storyboard approval does not define the latest style.

Map each beat to actor intent, causal action, reaction and change of information. Object metaphors must preserve that meaning. For example repeated phone checking needs anxiety/reach/privacy response, not generic chat cards. Dialogue follows approved-v18.md.
